<h2>双 ISP 服务器的搭建，重点在「两条出口怎么共存」</h2>
<p>单出口的搭建思路是「装好、配通、能上网」。双 ISP 不一样：你要让两个出口同时存在、各自能出网、并且能按规则决定哪个流量走哪个出口。这一步没做好，所谓的双 ISP 只是地址属性好看，内部并没有真正利用起来。</p>
<p>所以搭建的核心不是装系统，而是路由规划。先把「谁走哪条」想清楚，再动手配置。</p>

<h2>前提：确认两个出口都是真实可用的</h2>
<p>先分别验证每条出口：能不能出网、出口地址是不是预期的那一个、运营商是否与承诺一致。两条都单独验证通过，再谈组合。</p>
<p>这一步不能省。有的「双 ISP」实际只有一条线路真实可用，另一条是历史标识。如果一开始不验证，后面配置再精细也是在错误的前提上施工。</p>

<h2>网卡与地址的规划</h2>
<p>最清晰的做法是一条出口对应一张网卡，地址分别绑定，互不干扰。这样策略路由的规则容易写，排障时也能单独关掉一条出口做对照。</p>
<p>如果只有一张网卡，可以在同一网卡上绑定多个地址，靠策略路由区分。技术上可行，但排障难度明显上升，因为两张出口共享同一个设备队列，出问题时不容易判断是哪条线路的问题。</p>

<h2>策略路由：决定谁走哪条出口</h2>
<p>策略路由的作用是「按规则选路」，常见规则有三种：按源地址选、按目标地址选、按应用或用户选。实践中用得最多的是按源地址，也就是「这个网段或这个用户固定走出口 A」。</p>
<p>配置时要建立一个独立的规则表，与主路由表分开，避免互相覆盖。规则顺序很重要，通用规则要放在特例之后，否则特例会失效。</p>

<h2>健康检查与故障切换</h2>
<p>双出口的价值之一就是冗余，但如果没有任何检测，一条线路断了流量也不会自动切换，冗余等于不存在。所以需要配置健康检查：周期性探测每条出口的连通性，异常时把流量导向另一条。</p>
<p>切换策略有两种：全局切换（所有流量换到备用出口）和分组切换（只切换受影响的组）。多账号场景建议用分组切换，避免一次故障导致所有环境同时变更地址。</p>

<h2>代理服务怎么绑定出口</h2>
<p>代理服务本身可以选择从哪个源地址出网。要在配置里明确指定每个入站或每个用户走哪个出口，而不是依赖系统默认。默认行为通常只用主出口，双 ISP 就白配了。</p>
<p>如果代理服务不支持按用户指定出口，可以用策略路由按来源地址分流，效果相同但配置更绕。先看服务能力，再决定方案。</p>

<h2>关键配置项对照</h2>
<table>

<tr><td>策略路由表</td><td>按规则选路</td><td>流量全走默认出口</td></tr>

<p>最后一行是双 ISP 搭建里最常见的「假成功」：配置看起来都对，实际出网地址只有一个。判断标准只能是实测，不能看配置文件。</p>

<h2>验证四项</h2>
<p>一，从每个出口分别出网，确认出口地址与预期一致。二，断开其中一条，确认流量能切到另一条且服务不中断。三，恢复后确认能切回，且不会来回抖动。四，检查日志里能否区分两条出口的流量。</p>
<p>四项都通过，才算搭建完成。第三项尤其重要，切换后反复抖动比不切换更影响使用。</p>

<h2>常见的几个坑</h2>
<p>一是路由规则写反，表现为该走 A 的走了 B，日志里很难看出来。二是健康检查探测目标选错，探测的是本地网关（永远是通的），导致故障检测无效。三是切换时把所有连接一起断掉，正在执行的任务全部中断。</p>
<p>四是忘了更新反向路径过滤设置，导致某个出口的入向流量被丢弃。这类问题表现是「能出去但回不来」，排查时容易被误判成对方问题。</p>

<h2>上线后的维护</h2>
<p>定期检查两条出口的实际使用比例。如果长期只用了其中一条，说明分流规则没有真正生效，或者业务本身不需要双出口。后者的话，可以考虑降配省钱。</p>
<p>同时保留一份配置说明：哪条出口对应哪组业务、切换逻辑是什么、如何手工指定出口。这份文档在交接和应急时价值很高。</p>

<h2>常见问答</h2>
<h3>双 ISP 必须两条真实线路吗？</h3>
<p><strong>答：</strong>要让「双」真正发挥作用，是的。只有地址属性双标识而没有两条可用出口，内部并不具备冗余。</p>
<h3>单网卡能不能实现双出口？</h3>
<p><strong>答：</strong>能，靠多地址加策略路由。但排障更难，有条件时建议双网卡。</p>
<h3>切换会不会导致账号的登录地变化？</h3>
<p><strong>答：</strong>会。从 A 出口切到 B 出口，对外地址就变了。所以切换策略要考虑业务对地址稳定的要求。</p>
<h3>这套配置需要多强的机器？</h3>
<p><strong>答：</strong>不需要很强。转发与路由对性能要求不高，重点是网卡数量与稳定性。</p>
